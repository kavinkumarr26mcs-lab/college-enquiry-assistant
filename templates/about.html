About this project

Project {{ project_code }}: an FAQ-based enquiry assistant built as an academic Python project.

Project overview

The {{ project_name }} lets a visitor ask a question in natural language and returns the most relevant entry from an FAQ dataset, together with that entry's FAQ ID. It was prepared for {{ college_name }} {{ college_descriptor }}. It does not describe the institution's history, achievements or statistics, and it does not contain verified college data.

Objectives

  • Load an approved FAQ dataset from a JSON file and validate it.
  • Accept natural-language questions, including paraphrases.
  • Show the best answer with its unique FAQ ID.
  • Fall back honestly when no sufficiently reliable answer exists, and reject unrelated questions.
  • Keep the user interface separate from the core question-processing logic.
  • Allow the core system to be evaluated independently of the web application.

Technology stack

  • Language: Python
  • Backend: Flask, with a JSON API at POST /api/enquire
  • Retrieval: scikit-learn TF-IDF vectors and cosine similarity
  • Data: JSON files (FAQ dataset and evaluation questions)
  • Frontend: HTML5, CSS3 and vanilla JavaScript
  • Testing: pytest

How FAQ retrieval works

  1. The question is cleaned: lower-cased, punctuation and common filler words removed, and simple plurals reduced.
  2. It is converted into a TF-IDF vector and compared, using cosine similarity, with every FAQ question and its approved paraphrases.
  3. Each FAQ keeps its best score. The score is reduced when many words of the question are unknown to the FAQ vocabulary, so one shared word cannot carry an unrelated question.
  4. The top FAQ is returned only if its score reaches the confidence threshold{% if threshold is not none %} (currently {{ '%.2f'|format(threshold) }}){% endif %} and it clearly beats the runner-up. Otherwise the fallback message is shown.

The match confidence shown beside an answer is this similarity score. It is a measure of text overlap, not a probability that the answer is correct.

Limitations

  • FAQ answers{% if faq_count %} ({{ faq_count }} entries){% endif %} are taken from the college's published VETIAS Handbook 2024-25. Where the handbook does not publish a detail (fees, eligibility, scholarships and so on), the answer says so and points to the college office rather than guessing.
  • Matching is based on words, not meaning. Different vocabulary for the same idea, spelling mistakes and non-English questions can be missed.
  • Vague questions are rejected rather than guessed at, so some valid questions will receive the fallback.
  • The assistant has no memory of earlier messages; each question is answered on its own.
  • No login, personal data or question history is handled or stored.
